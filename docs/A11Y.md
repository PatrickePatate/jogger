# Accessibility and responsive behaviour

State after Task 59. This page says what is checked by a machine on every CI run, what was fixed, what was
looked at by hand, and what nobody has verified. An automated scan passing is not a conformance claim.

## Checked automatically

`tests/Browser/AccessibilityTest.php` (Dusk, runs in the CI `browser` job through `tests/Browser/run.sh`).
It signs in as an admin against seeded data: one installation, repository, pool, host, runner, and four jobs
(succeeded with a runner, queued, running, failed).

Pages covered: Overview `/`, Jobs `/jobs`, Job detail `/jobs/{id}` (the succeeded job), Pools `/pools`,
Hosts `/hosts`, Settings `/admin/settings`, and `/settings/security`.

1. **axe-core scan.** axe-core (npm devDependency, injected from `node_modules/axe-core/axe.min.js` by the
   WebDriver, never from a CDN) runs with its default rule set on each page, in the light and the dark theme,
   at 1400x1000. One extra state is scanned per theme: the account menu open. The test fails on any violation
   of impact `serious` or `critical` and prints rule id, impact, target selector and axe's summary.
   `moderate` and `minor` violations, and axe's "incomplete" (needs review) results, are **not** reported.
2. **Skip link.** On each page the first Tab stop is the "Skip to content" link, it is visible when focused,
   and Enter moves focus to `<main id="main">`.
3. **360 px viewport.** With the viewport emulated at 360x800 (CDP device metrics; a real Chrome window does
   not go that narrow), `document.documentElement.scrollWidth <= clientWidth` on each page, and every visible
   `<table>` either is a `.table-stack` whose rows are laid out as blocks (cards) and fits the viewport, or
   sits inside an ancestor with `overflow-x: auto|scroll`.

Run locally: `npm ci && npm run build && tests/Browser/run.sh --filter AccessibilityTest`.

## Fixed in this pass

Found by the axe scan (same findings in both themes unless noted):

| Rule | Impact | Where | Fix |
| --- | --- | --- | --- |
| `aria-allowed-attr` | critical | every page: `x-ui.dropdown` put `aria-expanded`/`aria-haspopup` on a wrapper `div` | the attributes are now set on the trigger button/link itself (`components/ui/dropdown.blade.php`) |
| `label-content-name-mismatch` | serious | every page: header search button had `aria-label="Open command palette"` over the visible text "Search ⌘K" | `aria-label` removed; the name is the visible text plus a visually hidden "(open command palette)" |
| `color-contrast` | serious | Job detail, light theme: success badge text 4.33:1 on its tint | `--color-success` darkened from `#0f7a57` to `#0b6848` (`resources/css/app.css`) |
| `definition-list`, `dlitem` | serious | Hosts: CPU/Memory `dl` groups contained non `dt`/`dd` children | the usage meter now lives in a second `dd` of the same group |

Found by the 360 px check:

- Pools: the card grid had an implicit `auto` column, so a long image name pushed the cards 9 px past the
  viewport. The grid now declares `grid-cols-1`.

Not found by a test, changed on inspection:

- `<main>` got `tabindex="-1"` so the skip link moves keyboard focus, not only the scroll position.
- The account menu button's only name was the user's initial. It now has a visually hidden "Account menu";
  the initial is `aria-hidden`.
- Focus ring token `--color-ring` (used by `x-ui.button`, which suppresses the default outline) was `#9aa3b2`
  on white, about 2.5:1. It is now `#6b7482` in the light theme and `#9aa3b2` in the dark theme. These ratios
  were computed by hand, not measured by a test, and the outer ring is drawn at 50% opacity, so the 1 px
  border carries most of the contrast.

## Checked by hand (reading the templates, not using assistive technology)

- **Status is not colour-only.** `x-job-status-pill`, `x-runner-state-pill` and `x-host-status-pill` all go
  through `x-status-pill`, which always renders an icon and a text label. Pool cards use a text badge
  ("Active"/"Paused"). Host and pool usage bars have `role="img"` with a text `aria-label`, and the same
  numbers are printed next to them. Only these components were read; status shown elsewhere (Insights
  charts, activity heatmap, audit log, deliveries) was not reviewed.
- **Focus visibility.** A global `:focus-visible` outline exists; inputs, selects and textareas replace it
  with a border and ring; buttons replace it with the ring token above. The command palette input has no
  focus indicator of its own (`outline-none focus:ring-0`); it is the only field in its dialog. Left as is.
- **Landmarks.** The app layout has one `main`, a labelled `aside` ("Main navigation") containing `nav`, and
  a `header`. axe's landmark rules are mostly `moderate`, so they are not enforced by the test.

## Not verified

- **No screen reader testing** (NVDA, JAWS, VoiceOver, TalkBack) of any page.
- **No full keyboard walkthrough.** Only the first Tab stop and the skip link are tested. That every control
  is reachable and operable by keyboard, focus order, focus trapping and focus return in modals, the command
  palette and the mobile navigation drawer, and arrow-key navigation inside `role="menu"` dropdowns (not
  implemented: items are reached with Tab) are all unverified.
- **Pages outside the list above**: Runners, Insights, Secrets, pool create/edit form, GitHub pages, admin
  Users/Teams/Audit log, Notifications, API tokens, first-run setup, sign-in and invitation pages, e-mails.
- **States not scanned**: modals, toasts, validation errors, empty states, the command palette, the mobile
  drawer open, the live log terminal while streaming (xterm.js), a job without a runner, paused pools,
  offline/revoked hosts, runners in other states. Contrast of badge tones not present in the seeded data
  is therefore unchecked, as is any contrast at the 360 px layout (axe runs at desktop width only).
- **Non-admin users**: the scan runs as an admin only.
- **Usability at 360 px** beyond "no horizontal page overflow": touch target sizes, truncated text, and
  whether stacked table cards read well were not assessed. No test on a real phone.
- Zoom to 200%/400%, text-spacing overrides, `prefers-reduced-motion` (a CSS rule exists, untested),
  forced-colors/high-contrast mode, and browsers other than Chromium.
- WCAG criteria that axe cannot judge (meaningful alt text and labels, error identification wording,
  reading order, timing of the 15 s polling refresh for screen reader users).
