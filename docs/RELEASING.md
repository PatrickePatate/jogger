# Releasing

A release is a GitHub release. Publishing one starts `.github/workflows/release.yml` and the runner image workflow.

## Steps

1. Make sure CI is green on `main`.
2. Move the "Unreleased" notes in `CHANGELOG.md` under the new version and commit.
3. Create the release. Notes are generated by GitHub from the merged pull requests and commits since the last tag:

   ```bash
   gh release create v1.2.0 --generate-notes
   ```

   For a trial run add `--prerelease` (use a tag such as `v1.2.0-rc.1`). A pre-release publishes versioned
   images but does not move `:latest`.
4. Watch the "Release" workflow. When it is done, check the release page.

## What a release publishes

| Artifact | Where |
|---|---|
| `ghcr.io/<owner>/jogger:<version>` and `jogger-agent:<version>` (amd64, arm64), plus `:latest` for a full release | GitHub Packages |
| `ghcr.io/<owner>/jogger-runner:<runner version>` and `:latest` | GitHub Packages (runner image workflow) |
| `jogger-agent-linux-amd64`, `jogger-agent-linux-arm64` | Release assets |
| `jogger-compose-<version>.tar.gz` (compose file, Caddyfile, example env file, install guide) | Release assets |
| `SHA256SUMS` | Release assets |

Verify a download with `sha256sum -c SHA256SUMS --ignore-missing`. `jogger-agent --version` prints the release version.

## Notes

- The version is the tag without the leading `v`.
- The packages must allow the repository to write to them (package settings → Manage Actions access) and be
  public for the install guide to work without a registry login.
- There is no separate test namespace: use a pre-release to try the workflow.
